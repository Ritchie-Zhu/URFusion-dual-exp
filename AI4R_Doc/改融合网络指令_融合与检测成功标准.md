# 改融合网络指令（先赢 A2，再做消融）

在锁定协议下改 **F 的 mixer**：默认保留双 `FusionPreNet`，重做 Dual 后面的融合块。可以做新 MoE（异构专家、不同输入、不同路由），也可以做别的融合块。A2 是必须打败的内部对照，不是终稿，也不能改名交差。文后列出的是已经训过的具体写法，禁止原样重训。

官方种子：Xu et al., URFusion, IEEE TIP 2025。本仓是灰度 Y + VIS 色度协议上的复现与探索。不要改 `vis-ir/code`，不要覆盖 `Fusion_noleak_1` 与官方 xlsx。

## 必须先赢的对照

**`Abl_DualMoE_wo_MoE`（旧称 A2）**：双 `FusionPreNet` + **一个** `FusionExpertBlock` + PostNet。它已经强于带同构 MoE 的 `Fusion_noleak_1`，常报六项上也已经压过外部对比方法。新方法必须先过它，不能只跟外部方法比。

三个融合测试集各自独立判定，缺一个集就不算过关：

- LLVIP `test_sample1000`（1000 张）
- MSRS `test`（361 张）
- M3FD `test`（300 张）

过关用的融合指标就是主表那六项（越高越好）：**NMI, Qy, MI, VIF, Qabf, VIFF**。数字见 `对照指标_融合25项与目标检测指标.md`。官方脚本仍会出 25 项，用来存档；**过关不看「25 项里任意挑六个」**。

## 两段流程（先主模型，后消融）

**第一段：主模型过关（还没过就不要开消融）**

1. **融合**：每一个测试集上，上述六项都高于 `Abl_DualMoE_wo_MoE`。NMI/MI 是 A2 赢 Full 的地方，不能只赢 VIF/Qabf/VIFF、NMI/MI 反而掉。
2. **检测**：同一套冻结 YOLO11s（`detection_dataset` 里的 `best.pt`），`test_iv_2000` 上 mAP50 与 mAP50-95 都高于 `Abl_DualMoE_wo_MoE`（约 0.802 / 0.516）。Visible（0.849）是上界，不是对照。过关不要求超过 LRRNet。

只赢其中一个测试集、或只赢融合输检测、或只赢检测输融合，都不过关。只靠把单卷积加宽刷 0.00x、或把旧结构改名，不算贡献。

**第二段：过关之后才做消融**

消融必须是**这个新主模型自己拆出来的**（去掉新模块 / 换成单 mixer 等）。旧的 A1、A2、S1、`Fusion_noleak_1` 不是它的消融，不要拿来充行。

消融表只看上述 **六个融合指标**，三个测试集都要报。主模型必须是表里最优的一行：去掉声称有用的模块后，六项应变差（至少 NMI 与 MI 要掉）。消融不必全员跑检测。

对照数字见 `对照指标_融合25项与目标检测指标.md`。不要重训外部对比方法或本仓已完成的对照。外部方法主表（MUFusion、U2Fusion、URFusion、MetaFusion、GIFNet、SAGE、LRRNet 等）A2 已经在六项上赢了；新模型若六项赢 A2，对外主表自然成立。

## 已做实验与机制（给新设计用，不要原样重训）

这些是人工已经跑完的对照。读机制，不要当「MoE 这条路废了」。六项数字见 `对照指标_融合25项与目标检测指标.md`。仓内现名见 `部署说明_仓库与数据集如何接路径.md`。

**站住的**

- **Dual 有效（A1 `Abl_DualMoE_wo_Dual`）**：两路 PreNet 合成一个共享编码器后，MSRS NMI 从 Full 的 0.710 掉到 0.684。新模型默认保留双 `FusionPreNet`。
- **协议有效**：灰度 Y + VIS Cb/Cr、C 只在训练监督、`training_noleak`。泄漏训练会虚高，不要改回 `datasets/training`。
- **损失分工（B1–B3，建在 Full 上）**：`L_int` 保 NMI/MI，`L_grad` 保 VIF/Qabf/VIFF，`L_branch` 约束两路特征、对六项几乎无增益。新主模型过关后再在自己身上重做损失消融，不要在 Full 上再扫 λ。

**A2 为什么强**

- 结构极简：concat(vis, ir, |diff|) 进一个 `FusionExpertBlock`。
- 相对 Full，三个测试集上 NMI/MI 都更高；VIF/Qabf/VIFF 也整体不差。
- 检测与 Full 几乎打平（约 0.802 / 0.516 vs 0.803 / 0.515）。检测救不了输在六项上的 MoE。

**失败的是具体写法，不是「专家」这个想法**

1. **`Fusion_noleak_1`（Full，同构 noisy top-2）**  
   四个相同的 `FusionExpertBlock`，输入都是 concat(vis, ir, |diff|)，noisy top-2 + `L_aux`。专家 hit 约 0.5，没有分工。NMI/MI 全面低于 A2。  
   **启发**：专家若同构、吃同一份输入，路由器没有理由分工。新 MoE 要让专家在输入或结构上真的不同。

2. **SpatialResMoE v1 / v2（`our_model_2_SpatialResMoE` 里未训满的两版）**  
   门控两轮打满（`g_mean=1`），不是代码崩溃。  
   **启发**：前 5 个 epoch 若门全开或全关，停训改设计，不要加 load-balance 硬拆已经饱和的门。

3. **SpatialResMoE_3（同目录训满的泄漏残差 MoE）**  
   `E_base(concat(f_cap, |diff|))` 再加 vis/ir unique 残差 + C-mask 路由。训练 HEALTH 可以 OK，主表 18 格全输给去掉残差的 S1（`Abl_SpatialResMoE_wo_Res`）。  
   **启发**：`|diff|` 已经把 unique 喂进 base，残差是重复通路。HEALTH OK ≠ 模块有用。S1 的 VIF/Qabf/VIFF 优于 A2，但 NMI/MI 仍低于 A2，所以 S1 也不能当终稿。

4. **SpatialResMoE_2（`our_model_3_SpatialResMoE_2`，leak-free 互斥）**  
   base 只吃 `f_cap`，互斥门 + `g.detach()` + C-mask。残差是活的，主表相对 S1 仍是 2 胜 16 负。  
   **启发**：堵住泄漏之后，互斥会丢掉另一侧 unique。这只否定「互斥 + detach + C-mask」这一捆，不否定非互斥的新残差或新 MoE。

5. **ConflictAdd_1（`our_model_4_ConflictAdd`）**  
   `B(f_cap) + a * R(concat vis,ir,|diff|)`，独立 sigmoid，无 detach。第 2 轮 `a_mean≥0.995`，人工停于 epoch 6。  
   **启发**：融合损失会把 A2 式残差打满，变成「A2 + 常开 skip」。这不是 MoE 失败，是门没有对抗目标。不要再对打满的门加 load-balance。

**设计时可以抓住的空档**

- 专家异构，或两路专家吃的不是同一份 concat。
- 路由要有真选择，且前几轮不能饱和；不要用 `L_aux` / load-balance 去救已经塌的门。
- 残差不要和已经进 base 的 `|diff|` 重复。
- 互斥不是必须的；非互斥、可叠加的跨模态交互还没有被证伪。
- 六项里信息量（NMI/MI）和结构量（VIF/Qabf/VIFF）会交换。只赢后三项、NMI/MI 掉，就是 Full / 旧 MoE 的失败模式。
- 仍缺、且只有新假设才值得做的一刀：mixer 输入 `concat(vis,ir)` vs `concat(vis,ir,|diff|)`。这是支撑输入的消融，不是新模型本身。

## 锁定协议（不要改）

- 训练：`datasets/training_noleak`，9987 pairs，batch 12，patch 160，80 epoch，Adam 1e-4，seed 1234，`num_workers` 12
- 冻结 C：`Vis_Content_noleak`、`ir_Content_noleak`。C 只在训练里监督 F。推理不跑 C，不要把 C 或 mask 放进 `model.forward`
- 推理：Y 融合 + VIS Cb/Cr（`metrics_save/llvip_sample1000/colorize_gray_infer.py`）
- 融合评测：`metrics_save/llvip_sample1000/run_eval_mp.py`，禁止 `eval_torch_fast`
- 检测评测：`metrics_save/yolo_det/eval_yolo_detection.py`，同一 `best.pt`，不要重训检测器
- 环境：`OMP_NUM_THREADS=1`，见 `运行环境_Python依赖与线程.md`
- 新实验单独建目录，不要改 `our_model_1_DualMoE/code` 里已锁定的 Full

损失默认与单 mixer 对照相同：`L_main + 0.1 L_int + 1.0 L_grad + 0.01 L_branch`。不要无故加回 `L_aux`。

## 不要原样重训的写法

禁止当主方法或原样重训（新 MoE 不在此列，只要不是下面这一捆）：

1. 多个同构 `FusionExpertBlock` + noisy top-2 / `L_aux`（即 Full）
2. `E_base(concat(f_cap,|diff|))` 再加 vis/ir unique 残差（SpatialResMoE_3）
3. leak-free base + 互斥门 + `g.detach()` + C-mask `L_route`（SpatialResMoE_2）
4. `B(f_cap)+a*R(concat vis,ir,|diff|)` 独立 sigmoid（ConflictAdd）
5. 用 load-balance 硬拆已经全开的门
6. 共享单编码器替代 Dual

不要把 loss 下降当成模块有用。门控前 5 个 epoch 若全开/全关，停训改设计。

## 流程

先陈述假设（新模块若换成单个 `FusionExpertBlock`，六项或检测应变差），再写代码。sanity：shape、Y 在 [0,1]、旧 ckpt 不能误加载。一次一个 80 epoch。满训后评测顺序：融合 MSRS → M3FD → LLVIP（先看六项是否全高于 A2），再跑检测 2000。六项或检测尚未赢 A2，不要开消融。过关后再训消融，三个测试集写清六项是否主模型最优。未经同意不要 `shutdown`、不要 push。
